## 2. 路径架构

验收实例设置：

```text
CLIPBOARD_SHELF_TEST_ROOT = <绝对路径>
```

统一派生：

```text
TEST_ROOT/
├── shelf.db            ← DB
├── config.json         ← config
├── images/
│   ├── full/           ← 图片原图
│   ├── thumb/          ← 缩略图
│   └── annotated/      ← 标注图
├── logs/
│   └── crash.log       ← 日志
├── backups/            ← 启动备份 + fingerprint
└── pet-tasks.json      ← 宠物任务
```

未设置 `CLIPBOARD_SHELF_TEST_ROOT` 时，全部路径回退生产 `%APPDATA%\clipboard-shelf`（行为与 v1.7/v1.8 现状完全一致）。

接入方式：

- 主进程启动最早期：`resolveRuntimePaths()` → 按模式 `app.setPath('userData', ...)` → `assertIsolatedRuntime()`；
- 由于 Electron userData 已指向 TEST_ROOT，`app.getPath('userData')` 的所有消费方（config/images/pet-tasks/encryption 回退/ocr 读取/backups）自动落到 TEST_ROOT；
- `db-service` / `encryption-service` 显式优先 TEST_ROOT，防止与 legacy 环境变量分叉。

## 3. 安全边界

`assertIsolatedRuntime()` 硬校验（任一失败 → abort）：

1. 验收实例必须设置 `CLIPBOARD_SHELF_TEST_ROOT`；
2. TEST_ROOT 必须存在；
3. TEST_ROOT 必须是绝对路径；
4. TEST_ROOT 不得等于生产 userData（`%APPDATA%\clipboard-shelf`）；
5. dbPath / configPath / imagesDir / logsDir / backupsDir / petTasksPath 全部位于 TEST_ROOT 内；
6. Electron userData 必须等于 TEST_ROOT；
7. legacy `CLIPBOARD_SHELF_USER_DATA`（若设置）必须与 TEST_ROOT 一致，否则 abort。

不做“约定小心”：所有验收实例路径由统一模块派生，且启动时强制校验。

## 5. 是否仍可能触碰生产 userData

- 通过 `CLIPBOARD_SHELF_TEST_ROOT` 启动的实例：**不能**（DB/config/images/logs/backups/pet-tasks/Electron userData 全部硬校验在 TEST_ROOT 内，任一越界即 abort）；
- 未设置 TEST_ROOT 的实例：**是生产模式**，等同现状（这不是“越界”，而是明确的生产运行）；
- 残余风险：
  1. 若有人以“生产模式”手动启动 win-unpacked 做冒烟（不设置 TEST_ROOT），仍会直接使用生产 userData —— 这属于操作纪律，无法由程序判定“意图”；
  2. 当前正在运行的历史 win-unpacked 实例（8/13 17:46 启动，旧构建、未含本加固）仍在生产 userData 上运行 —— 应确认其来源并自行决定处理；
  3. 验收入口应统一使用脚本/文档化命令设置 TEST_ROOT，避免手工漏设。

## 6. 下一步重新验收的 Gate

1. 建立独立 `TEST_ROOT`（绝对路径，含 db/config/images/full|thumb|annotated/logs/backups）；
2. 验收启动命令必须设置 `CLIPBOARD_SHELF_TEST_ROOT=<TEST_ROOT>`；
3. 启动前运行 `node scripts/acceptance-fingerprint.cjs` 生成指纹（保存到 `TEST_ROOT/backups/acceptance-fingerprint.json`）；
4. 应用启动时 `assertIsolatedRuntime()` 通过（打印实际 userData 路径；任一路径落入生产 → abort）；
5. 验收中所有 retention/删除/migration 类操作仅针对 TEST_ROOT；
6. 验收结束后再次运行指纹，对比 DB/config SHA-256 与图片计数，确认无生产接触；
7. 生产实例（正式安装 v1.7.0）与验收实例（TEST_ROOT）不同时运行。
