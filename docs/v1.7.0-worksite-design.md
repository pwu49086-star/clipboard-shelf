# Clipboard Shelf v1.7.0 Worksite 实施设计

> 状态：Design / 实施前规划（零代码修改）
> 基线：v1.6.1（已发布、已冻结，HEAD = 02926cf，git clean）
> 目标：把“临时多选输出”升级为“持久工作现场”：**选起来 → 归入现场 → 一键输出**

---

## 1. 产品目标

一行目标：

> 一次维修任务里复制的那十几段内容，能作为一个“现场”被记住、被打开、被一键输出。

不是任务管理器、不是看板、不是 AI。

核心闭环：

```text
复制（多段）→ 多选 → [加入现场] → 下次：打开现场 → 全选 → 复制全部/Markdown/导出/工单草稿
```

现场创建必须是“输出/归并动作的副产品”，不要求用户先建现场再复制。

---

## 2. migration v3 完整方案

沿用现有 `PRAGMA user_version` 迁移框架（`db-service.js` MIGRATIONS 数组，逐条 try/catch，重复列自动跳过）。

```js
{
  version: 3,
  sql: [
    `CREATE TABLE IF NOT EXISTS worksites (
       id INTEGER PRIMARY KEY AUTOINCREMENT,
       title TEXT NOT NULL,
       note TEXT DEFAULT '',
       archived INTEGER DEFAULT 0,
       createTime INTEGER NOT NULL,
       updateTime INTEGER NOT NULL
     )`,
    'CREATE INDEX IF NOT EXISTS idx_worksites_update ON worksites(updateTime DESC)',
    'ALTER TABLE items ADD COLUMN worksiteId INTEGER',
    'CREATE INDEX IF NOT EXISTS idx_items_worksite ON items(worksiteId)'
  ]
}
```

要求：

- 旧库（v2）无损升级：items 全部 `worksiteId = NULL`，数据/实体/FTS 不变；
- 幂等：重复执行不报错（CREATE IF NOT EXISTS + ALTER 重复列被框架 try/catch 跳过）；
- 空库：直接到 v3；
- 不建外键（与现有表风格一致，删除联动由代码保证）；
- 不建 junction 表（v1.7 单归属）。

## 3. 数据库 schema（v3 全貌）

### 新增

```sql
CREATE TABLE worksites (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  title TEXT NOT NULL,
  note TEXT DEFAULT '',
  archived INTEGER DEFAULT 0,      -- 0 进行中 / 1 已归档
  createTime INTEGER NOT NULL,
  updateTime INTEGER NOT NULL
);
CREATE INDEX idx_worksites_update ON worksites(updateTime DESC);

-- items 新增列（可空）
ALTER TABLE items ADD COLUMN worksiteId INTEGER;
CREATE INDEX idx_items_worksite ON items(worksiteId);
```

### 不新增

- `worksite_items` 关系表（v1.7 不做多归属）
- worksite 实体快照（现场级实体用现有 entities 派生查询）
- 任何内容复制（worksite 只存关联，不存剪贴板文本）

## 4. rollback 方案

| 层 | 方案 |
|---|---|
| 代码 | git 回退到 v1.6.1 提交，重启应用 |
| 数据库 | **无需反向迁移**：migration v3 纯增量（新表 + 可空列）。旧代码 `SELECT *` 读到多余列不处理、insert 显式列名不受影响，可安全运行 |
| 数据 | 生产库迁移前执行一次现有启动备份 + 手动副本到 `release/v1.7.0-pre-migration-backup/` |
| 副作用 | 回退后现场保护规则失效（旧代码清非收藏会删到现场记录）——回退属临时状态，需提示用户 |

## 5. retention 修改方案

**不改 `retention.js` 核心算法，只改 `db-service.js` 的清理查询。**

规则：**现场内记录（`worksiteId IS NOT NULL`）等同收藏，永不自动清理；用户手动删除不受限。**

### 5.1 `cleanByPolicy`（3 处候选查询各加一个条件）

```sql
-- maxDays 候选
WHERE isFavorite = 0 AND worksiteId IS NULL AND createTime < ?
-- maxItems 候选
WHERE isFavorite = 0 AND worksiteId IS NULL ORDER BY createTime ASC LIMIT ?
-- maxImageItems 候选
WHERE type = 'image' AND isFavorite = 0 AND worksiteId IS NULL ORDER BY createTime ASC LIMIT ?
```

### 5.2 `clearNonFavorites`（用户主动清空）

```sql
SELECT id, filePath, thumbPath FROM items WHERE isFavorite = 0 AND worksiteId IS NULL
DELETE FROM items WHERE isFavorite = 0 AND worksiteId IS NULL
```

（现场记录视为“工作中资料”，清空非收藏也不删；用户需先移出现场。）

### 5.3 归档与清理的关系

归档只改 `archived` 标记，**不解除关联、不影响保护**。后续若需要“归档后自动释放保护”，单独设计，v1.7 不做。

## 6. IPC / API 最小变更

### 6.1 新增 IPC（main → renderer）

```text
worksites:list()                       → [{id,title,note,archived,createTime,updateTime,itemCount,lastItemTime}]
worksites:create({title,note})         → worksite row
worksites:update(id,{title,note,archived}) → updated row
worksites:delete(id)                   → 解除全部关联 + 删除现场（不删记录）
items:setWorksite(ids[], worksiteId|null) → 批量加入/移出（null = 移出）
```

### 6.2 preload 新增 5 个白名单包装

```text
worksitesList / worksitesCreate / worksitesUpdate / worksitesDelete / setItemsWorksite
```

### 6.3 `getAll` 扩展（复用现有透传，IPC/preload 的 getAll 零改动）

```js
getAll({ ..., worksiteId = null })
```

- 不传 / null → 行为完全不变（不过滤）；
- 正整数 → `AND i.worksiteId = ?`（加密路径同样在内存过滤后追加条件）；
- 现场视图与实体过滤/关键词/type/favorite 全部 AND 组合；
- v1.7 不做“未分配”视图（`worksiteId = 0` 语义留后续）。

## 8. 现场创建 / 加入 / 移除 / 归档 / 删除流程

| 动作 | 流程 | 数据结果 |
|---|---|---|
| 创建 | 批量栏「加入现场」→ 新建现场（标题必填，备注可选）→ 确定 | `worksites.insert` + 所选 ids `UPDATE worksiteId` |
| 加入 | 批量栏「加入现场」→ 选择已有现场 → 确定 | 所选 ids `UPDATE worksiteId = 现场id` |
| 移除 | 现场视图多选 → 「移出现场」 | `UPDATE worksiteId = NULL`（记录留在历史） |
| 归档 | 现场列表行操作 → 确认 | `archived = 1`（关联与保护不变） |
| 取消归档 | 行操作 → `archived = 0` | 同上 |
| 删除现场 | 行操作 → 确认文案“解除 X 条记录关联，不删除记录” | 全部关联置 NULL + 删 worksite 行 |
| 删除记录 | 现场视图内正常删除 | 记录删除，现场计数自然减少 |

失败处理：标题为空阻止创建；批量 attach 按 500 分块；任一条失败整体回滚（单事务）；toast 提示。

## 9. 与现有多选输出的连接方式

**零改造连接**：现场视图就是普通 `ItemList`，多选/输出全部走现有链路。

```text
现场视图 items = getAll({ worksiteId, withEntities: true, sort: 'time', limit: 5000 })
全选 → selectedIds（Set 顺序）→ fetchSelectedItems（getAll({ids}) 分块）→
       collection-output.buildPlainText/buildMarkdown/buildWorkOrderDraft → 复制/导出
```

- 现场内全选 + 工单草稿 = “一键输出整个现场”，完全复用 v1.6.1 已验收管道；
- 现场创建入口长在批量栏，是“输出动作的副产品”，不增加新的前置仪式。

## 10. 隐私门禁

| 项 | 规则 |
|---|---|
| worksiteId | 不是内容字段，不参与加解密；加密锁定态下现场视图按现状显示空内容 |
| sensitivity=1 | 现场视图与主列表一致：默认打码，可手动显示 |
| sensitivity=2 / metadataOnly | 现场视图不显示内容；全选输出时被 collection-output 门禁排除（现有逻辑，零改动） |
| 现场标题/备注 | 用户主动输入，仅本地 SQLite 存储，不上传 |
| 实体 | 现场视图 Chip 复用现有实体（敏感记录本就不产生实体） |
| 新增采集 | 无：不新增窗口标题、不扫描目录、不读文件内容 |

## 11. 测试矩阵

### Migration

- 空库 → v3
- v2 真实结构（含 2000+ items / entities / FTS）→ v3：items 数、favorites、FTS、entities 不变，`worksiteId` 全 NULL
- 重复 migration 幂等（重复执行 user_version 仍为 3，无报错）
- 迁移后 CRUD 正常

### Worksite CRUD / 关联

- create（含空标题拒绝）
- update title/note/archived
- list 返回 itemCount / lastItemTime 正确
- delete 解除关联（items 保留、worksiteId=NULL、实体不变）
- setItemWorksite 批量加入 / 移出（含 500+ ids 分块）
- 删除记录后 worksite itemCount 减少

### getAll 组合

- `worksiteId` 单独过滤
- `worksiteId + search`（英文 FTS 与中文 LIKE 两条路径）
- `worksiteId + entityFilters`（AND）
- `worksiteId + type / favorite`
- `withEntities` 在 worksite 视图正确挂实体
- `sort:'time'` 严格倒序

### Retention

- cleanByPolicy maxItems：现场内记录不被删，现场外照删
- cleanByPolicy maxDays / maxImageItems：同上
- clearNonFavorites：现场内记录保留
- 移出现场后：恢复可被清理

### Privacy / 输出

- 现场视图全选输出：sensitivity=2 / metadataOnly / null 排除
- 加密锁定态：现场视图无内容泄露
- 现场内记录删除 → entities 级联、FTS 同步（回归现有）

### 回归

- 原 147 测试全部保持通过
- 实体 Chip / 实体搜索 / AND / 型号历史 / 收藏 / 便签 / 图片 / source / retention / 删除联动无回归

## 12. 实机验收方案

1. 复制 5 段维修现场内容（型号/故障码/检测/图片）→ 多选 → 「加入现场」→ 新建「大金 U4 西湖区」；
2. 现场 Tab 显示该现场：记录数正确、Chip 正常、时间倒序；
3. 现场内全选 → 工单草稿：分类正确、顺序正确、处理过程留空；
4. 现场内全选 → 导出 Markdown：对话框、文件内容、打开所在文件夹；
5. 加入一条敏感记录：现场视图打码、输出被排除；
6. 移出现场 / 归档 / 删除现场：记录均保留在历史，关联正确清空；
7. retention 验证：临时调低 maxItems 触发清理，现场内记录不删；
8. 重启应用：现场与关联持久保留；
9. 回归：普通复制、图片、搜索、实体过滤、收藏、便签、删除、加密、托盘。
