## 0. 事故根因摘要（供本文档上下文）

1. 测试隔离只覆盖数据库：`CLIPBOARD_SHELF_USER_DATA` 仅被 `db-service.js` 与 `encryption-service.js` 读取；
2. `config.json` 的写入（`saveConfig()`）与读取使用 `app.getPath('userData')`，**不受该环境变量影响**；
3. 冒烟阶段调用 `settings:setRetention({maxItems:1})` → `index.js` 把 retention 写入**生产 config.json**；
4. 随后一次未携带隔离变量的 win-unpacked 启动实例，以生产 config（maxItems=1）+ 生产 DB 启动 → `retention.start()` 立即执行清理 → 删除约 2400 条非收藏记录并 unlink 图片文件；
5. 生产库已从 `backups/shelf-2026-08-11T10-44-34.db`（2421 items / 205 images）恢复；约 205 张图片文件永久丢失（接受现状，不做恢复性写操作）。

## 四、图片资产保护审查

1. **当前备份是否包含图片**：❌ `backupDatabase()` 仅复制 `shelf.db + config.json`；`images/full|thumb|annotated` 从不进入备份（既有已知限制，事故中已实际暴露）。
2. **数据库恢复后图片可否恢复**：❌ 文件被 unlink 后无法从任何现有备份恢复；DB 仅保留元数据（文件名、OCR 文本 158/205、来源、实体）。
3. **图片文件与 DB 是否有一致性校验**：❌ 当前没有任何启动/扫描校验“DB 行 ↔ 磁盘文件”的机制（孤儿文件与缺失文件均静默）。
4. **是否需要完整备份方案**：✅ 建议（属 backlog，不在本版本实施）：完整备份应含 images/，并增加“图片行↔文件”一致性巡检与缺失报告。

## 六、v1.8.0 再验收准入条件（Gate）

### 6.1 强制：完整测试根目录隔离

任何验收/冒烟实例必须满足：

```text
TEST_ROOT
├── db
├── config
├── images
│   ├── full
│   ├── thumb
│   └── annotated
├── logs
└── backups
```

- DB、config、images、logs、backups 全部位于同一个独立 TEST_ROOT；
- **不得只隔离 DB**；
- 通过环境变量或启动参数同时覆盖：数据库路径、config 路径、images 路径、日志路径、备份路径；
- Electron `app.getPath('userData')` 也需指向 TEST_ROOT（在启动早期统一 setPath，优先于任何业务组件读取）。

### 6.2 强制：启动前自检与 abort

- 启动前打印并验证实际 userData 路径；
- 启动前验证 DB / config / images 三者路径全部位于 TEST_ROOT；
- 任一路径落入生产 `%APPDATA%\clipboard-shelf`：**立即 abort，不启动任何服务**；
- retention 测试、删除测试、migration 测试只允许在 TEST_ROOT 内执行；
- 验收脚本任何环节禁止调用 `settings:setRetention` 指向生产 config 的路径。

### 6.3 建议（backlog，不在本版本实施）

- 增加 `TEST_ROOT` 统一隔离入口（如 `CLIPBOARD_SHELF_TEST_ROOT` 或启动参数），由 main 入口统一解析并 setPath；
- 图片备份纳入完整备份方案；增加“DB 行↔文件”一致性校验；
- 验收前对生产 config/DB/images 做只读指纹快照，验收后复核未变化。
